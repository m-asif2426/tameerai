## 1. Migration Strategy & Principles

1. **No Raw `Base.metadata.create_all()`:** In production and cloud environments like Supabase, using `create_all()` bypasses version tracking, prevents reversible downgrades, and fails when tables evolve. Alembic will manage 100% of schema DDL.
2. **Foreign Key Order Compliance:** Tables with no incoming foreign keys are created first; child tables are created after parent tables.
3. **Zero Data Destruction:** Migrations strictly execute `CREATE TABLE`, `CREATE INDEX`, and `ADD CONSTRAINT`. Existing database objects (such as `alembic_version` and the `vector` extension) are preserved.
4. **Offline SQL Review:** For every migration revision generated by `alembic revision --autogenerate`, the generated Python script must be inspected and verified before applying with `alembic upgrade head`.

## 4. Phased Migration Batches (19 Tables)

Rather than creating a monolithic 19-table migration at once, migrations will be structured in focused, independently testable revisions across sub-phases 01C.2 through 01C.5:

### Revision 01: Core Identity, Settings & Sessions (3 Tables)
- **Tables:** `users`, `user_settings`, `user_sessions`.
- **Primary Constraints:**
  - `users.email` UNIQUE.
  - `user_settings.user_id` UNIQUE (Strict 1:1).
- **Rationale:** Establishes tenant accounts required to own all downstream engineering artifacts.

### Revision 02: Projects, Membership, Activities & Documents (4 Tables)
- **Tables:** `projects`, `project_members`, `project_activities`, `documents`.
- **Primary Constraints:**
  - `projects.code` scoped via `UNIQUE(user_id, code)`.
  - `documents.code` scoped via `UNIQUE(project_id, code)`.
  - `project_members` scoped via `UNIQUE(project_id, user_id)`.
- **Rationale:** Sets up project workspaces, file submittals, and team collaboration.

### Revision 03: Engineering Intelligence (8 Tables)
- **Tables:**
  - `material_rates` (Commodity benchmark rates).
  - `compliance_audits`, `compliance_findings` (PBC 2021 compliance dossiers & CAD pins).
  - `contract_analyses`, `contract_risk_cards` (FIDIC risk matrix & clause findings).
  - `boq_analyses`, `boq_items` (Itemized bill of quantities & variance tracking).
  - `reports` (Multi-disciplinary engineering consulting dossiers).
- **Primary Constraints:**
  - `compliance_findings.code` scoped via `UNIQUE(audit_id, code)`.
  - `contract_risk_cards.code` scoped via `UNIQUE(analysis_id, code)`.
  - `reports.code` scoped via `UNIQUE(project_id, code)`.
- **Rationale:** Houses domain-specific engineering records matching the frontend dashboard views.

### Revision 04: AI Conversational Chat & Vector Knowledgebase (4 Tables)
- **Tables:**
  - `chat_sessions`, `chat_messages` (Bilingual engineering assistant history).
  - `knowledge_sources`, `document_chunks` (pgvector semantic embeddings).
- **Primary Constraints:**
  - `document_chunks.embedding` parameterized as `vector` (dimensions finalized upon embedding model benchmarking).
  - `document_chunks` scoped via `CHECK ((knowledge_source_id IS NOT NULL AND project_id IS NULL AND project_document_id IS NULL) OR (knowledge_source_id IS NULL AND project_id IS NOT NULL AND project_document_id IS NOT NULL))`.
- **Rationale:** Wires multi-turn bilingual chat history and RAG document grounding with mathematical multi-tenant separation.

## 5. Reversible Downgrade Strategy

Every generated Alembic revision must contain a matching `downgrade()` function:
```python
def downgrade() -> None:
    # Drops tables in reverse dependency order
    op.drop_table('compliance_findings')
    op.drop_table('compliance_audits')
    ...
```
This guarantees safe rollbacks during staging and test execution without database corruption.
