# TameerAI — Backend Architecture & System Design (Phase 00)

**Project:** TameerAI — Pakistan Construction Compliance & Cost Intelligence Platform  
**Target System:** Modular Monolith Backend  
**Core Technologies:** Python 3.12, FastAPI, PostgreSQL 16 + pgvector, SQLAlchemy 2.0 (Async), Alembic, LangChain, LangGraph  

---

## 1. Architectural Principles & Overview

To maintain high development velocity, operational simplicity, and code maintainability for this Final Year Project, TameerAI is architected as a **Modular Monolith**.

### Core Tenets:
1. **Single Deployable Unit:** All API services, AI orchestration, and database access live in one structured codebase, avoiding unnecessary microservice overhead (network latency, distributed transactions, multiple containers).
2. **Domain-Driven Boundary Separation:** Modules (Auth, Projects, Documents, Compliance, Contracts, Costs, Reports, Chat) have distinct models, schemas, repositories, and services with minimal cross-module coupling.
3. **Asynchronous I/O:** Built upon `asyncio`, `FastAPI`, and `asyncpg` for high concurrency during AI streaming and file processing.
4. **Verifiable RAG Grounding:** Every compliance recommendation or contract risk alert generated by an agent must be backed by traceable citations (Document ID, Chapter, Section, Page number) stored in `pgvector`.
5. **Bilingual Native:** Data models and agent prompts natively support parallel English and Urdu text.

## 3. Configuration & Environment Management

Using `pydantic-settings`, configuration is strictly validated on application startup.

### Proposed Configuration Model (`app/core/config.py`):
```python
from pydantic_settings import BaseSettings, SettingsConfigDict
from pydantic import PostgresDsn, computed_field

class Settings(BaseSettings):
    PROJECT_NAME: str = "TameerAI Backend"
    API_V1_STR: str = "/api/v1"
    SECRET_KEY: str
    ALGORITHM: str = "HS256"
    ACCESS_TOKEN_EXPIRE_MINUTES: int = 60 * 24 * 7  # 7 days
    
    # Database
    POSTGRES_SERVER: str = "localhost"
    POSTGRES_PORT: int = 5432
    POSTGRES_USER: str = "postgres"
    POSTGRES_PASSWORD: str
    POSTGRES_DB: str = "tameerai"
    
    @computed_field
    @property
    def SQLALCHEMY_DATABASE_URI(self) -> str:
        return f"postgresql+asyncpg://{self.POSTGRES_USER}:{self.POSTGRES_PASSWORD}@{self.POSTGRES_SERVER}:{self.POSTGRES_PORT}/{self.POSTGRES_DB}"

    # AI & LLM Providers
    GEMINI_API_KEY: str
    EMBEDDING_MODEL: str = "models/text-embedding-004"
    LLM_MODEL: str = "gemini-1.5-pro"
    
    # CORS
    BACKEND_CORS_ORIGINS: list[str] = ["http://localhost:3000", "http://127.0.0.1:3000"]
    
    # Storage
    UPLOAD_DIR: str = "uploads"
    
    model_config = SettingsConfigDict(env_file=".env", case_sensitive=True, extra="ignore")

settings = Settings()
```

## 4. Database Architecture & Vector Search (`pgvector`)

### 4.1 Relational Schema Design
```
 +---------------+       1:N       +----------------+
 |     users     |---------------->|    projects    |
 +---------------+                 +----------------+
   |             \                   |            \
   | 1:N          \ 1:N              | 1:N         \ 1:N
   v               v                 v              v
+-------------+  +---------------+ +------------+ +--------------------+
| chat_sessions|  | user_settings | | documents  | | compliance_audits  |
+-------------+  +---------------+ +------------+ +--------------------+
       |                                 |                  |
       | 1:N                             | 1:N              | 1:N
       v                                 v                  v
+-------------+                    +------------+ +--------------------+
|chat_messages|                    | doc_chunks | |  compliance_rules  |
+-------------+                    | (pgvector) | +--------------------+
                                   +------------+
```

### 4.2 Key Database Models

1. **`users`**:
   - `id` (UUID PK), `email` (Unique), `hashed_password`, `full_name`, `role`, `company`, `pec_number`, `city`, `is_active`, `created_at`.
2. **`projects`**:
   - `id` (String PK, e.g. `PRJ-001`), `user_id` (FK), `name`, `name_urdu`, `location`, `city`, `type`, `type_urdu`, `budget_crore`, `budget_raw`, `spent_crore`, `status`, `risk`, `compliance_score`, `floors`, `area_sqft`, `engineer`, `created_at`.
3. **`documents`**:
   - `id` (String PK), `project_id` (FK), `name`, `file_path`, `file_type`, `file_size`, `uploaded_by`, `status`, `created_at`.
4. **`document_chunks` (Vector Store for RAG)**:
   - `id` (UUID PK), `document_id` (FK, nullable for regulatory library), `library_type` (`pbc_2021`, `fidic`, `pec`, `project`), `chapter`, `section`, `page_number`, `content`, `content_urdu`, `embedding` (Vector dimension 768 / 1536).
   - **Vector Index:** `CREATE INDEX ON document_chunks USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);`
5. **`compliance_audits` & `compliance_rules`**:
   - Audit metadata and individual checked items with `pin_x`, `pin_y`, `variance`, `reference_code`, `remedy`, `remedy_urdu`.
6. **`contract_risk_cards`**:
   - Flagged FIDIC/PEC clauses, `raw_snippet`, `risk_level`, `impact_metric`, `recommendation`.
7. **`material_rates`**:
   - City (`Lahore`, `Karachi`, `Islamabad`), `material_name`, `rate_pkr`, `unit`, `trend`, `change_pct`, `recorded_date`.

## 6. LangGraph Multi-Agent Orchestration Architecture

To conduct complex audits and answer technical engineering queries, a **LangGraph StateGraph** coordinates specialized domain agents:

```
               [ User Prompt / Audit Job ]
                           │
                           ▼
                 ┌──────────────────┐
                 │ Supervisor Agent │
                 └──────────────────┘
                 /         │        \
                /          │         \
               ▼           ▼          ▼
     ┌─────────────┐ ┌───────────┐ ┌─────────────┐
     │ Compliance  │ │ Contract  │ │    Cost     │
     │ Agent (PBC) │ │Agent(FIDIC│ │ Agent (BOQ) │
     └─────────────┘ └───────────┘ └─────────────┘
               \           │          /
                \          │         /
                 ▼         ▼        ▼
                 ┌──────────────────┐
                 │ Synthesis & Urdu │
                 │ Translation Node │
                 └──────────────────┘
                           │
                           ▼
          [ Grounded Response + Citation Cards ]
```

### Agent Roles:
1. **Supervisor / Router Node:** Classifies intent (Building Code, Contract, Cost, or Full Audit) and dispatches to domain agents.
2. **Compliance Agent:** Retrieves relevant PBC 2021 chapters via pgvector, cross-references measurements against regulations (e.g. Table 4.1 stair width, seismic zone factor), and outputs violation status with exact clause references.
3. **Contract Risk Agent:** Scans legal text against FIDIC Red Book standard provisions (e.g. Sub-Clause 8.7 liquidated damages, Clause 14 payment terms), identifies missing liability caps, and highlights contractor risk exposure.
4. **Cost Intelligence Agent:** Extracts BOQ line items, queries current steel and cement market indices for the specified city (Lahore, Karachi, Islamabad), and computes variance percentages.
5. **Synthesis & Translation Node:** Compiles findings into standard frontend-ready schemas (`WarningCard`, `Citation`, `remedyUrdu`) and ensures bilingual accuracy.

## 7. Testing & Quality Assurance Architecture

1. **Unit Tests (`tests/unit/`):**
   - Password hashing and JWT token verification.
   - Pydantic schema validation for all request/response models.
   - BOQ cost variance mathematical calculations.
2. **Integration Tests (`tests/integration/`):**
   - FastAPI endpoints testing using `httpx.AsyncClient` with an in-memory test database (`sqlite+aiosqlite` or isolated test PostgreSQL container).
   - Project CRUD and document upload flows.
3. **AI Evaluation Tests (`tests/ai/`):**
   - Ground truth benchmark tests against known Pakistan Building Code scenarios (e.g. checking 3.5 ft stair width against Section 4.2.1).
   - Citation verification tests ensuring responses do not hallucinate non-existent PBC clauses.
